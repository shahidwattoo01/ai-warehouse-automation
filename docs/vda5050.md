# VDA 5050 robot interface

Backlog PR-12. [VDA 5050](https://github.com/VDA5050/VDA5050) is the open standard between a
fleet manager ("master control") and driverless robots (AGVs / AMRs) from any manufacturer: JSON
messages over MQTT. This platform now speaks it on both sides: **every simulated robot is a VDA
5050 vehicle**, and the platform is **master control**. Code: [`integration/vda5050/`](../integration/vda5050/),
service `apps/backend/app/services/vda5050.py`, API `/api/v1/vda5050`, the **Integration** page.

## Topics and messages (version 2.0.0)

`uagv/v2/WarehouseAI/{robot}/{topic}`, for example `uagv/v2/WarehouseAI/R7/state`.

| Topic | Direction | Here |
|---|---|---|
| `order` | master → vehicle | Sent when the dispatcher assigns an order: node 0 the robot's position, one node per pick face (named by rack location, e.g. `A-21-12`), the packing station last; edges between them; even / odd sequence ids |
| `instantActions` | master → vehicle | `startPause` / `stopPause` pause and resume the robot in the simulator; `stateRequest`, `factsheetRequest` answer at once; `cancelOrder` is refused (FAILED): a picked tote cannot be dropped in this simulator |
| `state` | vehicle → master | Every 10 ticks and at once after a change: order and update id, last node, remaining nodes and edges, position (m, map `warehouse`), driving / paused, load, action states, battery, errors, `safetyState.eStop` (REMOTE while the fleet e-stop holds it) |
| `connection` | vehicle → master | `ONLINE`, retained; the platform's MQTT last will is `CONNECTIONBROKEN` |
| `factsheet` | vehicle → master | AMR-500 (simulated): kinematics, size, speed, supported actions; retained |

Every message has the standard header: `headerId` counting up per topic and vehicle,
`timestamp`, `version`, `manufacturer`, `serialNumber`. Orders are checked on the vehicle
(required fields, even node / odd edge sequence ids, one edge per pair of nodes, increasing
`orderUpdateId`); a rejected order shows as a `validationError` in the vehicle's state. Master
control checks every incoming state and counts invalid ones.

## Transport

* **In-process bus** (default, `MQTT_URL` empty): vehicles and master control exchange the same
  JSON in memory. Everything works and is tested without a broker.
* **MQTT** (`MQTT_URL=mqtt://user:password@host:1883`, `mqtts://` for TLS): the same messages on
  a real broker (paho-mqtt). Incoming messages are queued on the network thread and handled on the
  simulator's loop. `docker compose up` starts a Mosquitto broker on 127.0.0.1:1883 and points the
  backend at it. Real vehicles or another fleet manager on that broker see and can answer the
  simulated fleet.

**Tested:** the message rules, the order round trip, instant actions acting on the simulator,
invalid orders, topic matching and retained messages (`tests/unit/test_vda5050.py`); the MQTT
transport against a stand-in client (connect, resubscribe, last will, publish, the inbox drained
on the loop). The MQTT path has **not yet been run against a real broker** on the development
machine (no Docker there); `docker compose up` is the first place it runs end to end.

## Security

A networked broker needs TLS (port 8883), a password file or client certificates, and an ACL per
vehicle (each vehicle may publish only its own state / connection / factsheet and read only its
own order / instantActions). The compose broker is anonymous but published on this machine only.

## Not yet

* Real robots: the simulated vehicles follow the simulator's own routing; a real AMR would plan
  its own path between the order's nodes, and the master would release the order's horizon in
  steps (`released: false` nodes).
* `visualization` messages and map distribution; order updates (`orderUpdateId` > 0) from master
  control; zone sets.
