# Model cards

One card per model in the platform, in the spirit of *Model Cards for Model Reporting*
(Mitchell et al., 2019): what the model is for, what it was trained on, how well it does on
held-out data compared with a simple baseline, and where it should not be trusted.

| Card | Model (live version) | Task | Headline test result |
|---|---|---|---|
| [eta.md](eta.md) | ETA v1 · Gradient Boosting | ticks from assignment to delivery | MAE 38.8 vs 65.4 baseline |
| [late_risk.md](late_risk.md) | Late risk v1 · Logistic Regression | will an order be late? | F1 0.90, ROC-AUC 0.988 |
| [demand.md](demand.md) | Demand v1 · Gradient Boosting (+ v2 network, opt-in) | orders in the next hour | MAE 8.51 vs 10.34 baseline |
| [anomaly.md](anomaly.md) | Anomaly v2 · LSTM (v1 XGBoost fallback) | is a robot developing a fault? | F1 0.835 vs 0.813 (v1) |
| [vision.md](vision.md) | Vision v1 · YOLO11s | robots, workers, hazards in camera frames | mAP@0.5 0.908 |

**Common to all models**

* **Data:** dataset v3, generated by the platform's own simulator: 91 consecutive simulated days
  (7 Sep - 6 Dec 2026), large layout (80 × 50 m, 40 robots), weekday, seasonal and promotion
  effects (Singles Day, Black Friday, Cyber Monday). No personal data.
* **Splits by time, never at random:** train = first 63 days, validation = next 14 days (model
  and threshold choices), test = last 14 days (reported once). The vision dataset is split by
  simulation run.
* **Sim-to-real:** every result is measured in the simulator. A real site needs retraining (or
  at least validation) on its own data before any model drives decisions.
* **Where results come from:** `models/*_report.json` and `models/vision_yolo_v1/`, written by
  the notebooks in `notebooks/`.
